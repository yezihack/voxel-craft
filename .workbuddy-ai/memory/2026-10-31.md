# 2026-10-31

## 附魔台与自定义词条系统

新增一个能放置、能合成、能右键交互的方块（id 85），外加一套 8 条词条的铭刻系统，
逐条接进已有的伤害 / 挖掘 / 护甲 / 摔伤 / 掉落 / 盾牌 / 弓箭机制，可存档、有面板。

### 核心取舍：词条记在「装备种类」上，同类共享
`inv` 是 `id → 数量` 的 Map，`invSlots` 只存 id —— **没有单件物品的身份**。
要做「给这一把剑附魔」，就得给每格加实例对象，改动会顺
`invSlots` / 存档 / 合成格 / 盔甲槽 / 快捷栏一路铺开，收益远小于风险。
所以规则定成同类共享，界面上照实说明（换把新剑不用重刻，是便利不是漏洞）。

### 八条词条（一一对应已有机制，不做纯数字装饰）
锋利→`attackDamage` / 效率→`toolSpeedOn` / 守护→`armorPoints` / 轻羽→摔落 /
吸血→`tryAttackMob` 击杀 / 幸运→掉落 / 弓术→`fireArrow` / 坚守→盾牌格挡。

两个刻意的数值决定：
- 效率**乘算**（钻石镐 ×8 → 效率 III ×20）。加算的话星陨镐(16) 只到 17.5，
  越好的工具词条越没意义。
- 成本 = 基础 × 目标等级，让「各铺一个 I 级」和「堆到 III」成为两种花法。

### 这次踩到的坑
- **`setOpenEnchantHook()` 不能写在模块顶层**：`actions → mobs → input → uiActions →
  actions` 已成环，顶层调用撞 TDZ（`Cannot access 'onOpenEnchant' before
  initialization`）。改由 `boot()` 调 `installEnchantHook()`。
- **`requestPointerLock()` 现在返回 Promise**：无手势时 reject →
  `unhandledrejection` → fatal 兜底把英文报错糊满屏幕。加 `requestLockSafe()` 接住。
- **HMR 的 `?t=` 让探针拿到另一个模块实例**：现象是「词条刻上了但伤害一点不变」，
  极具误导性。除了重启 dev server，探针还要从 `performance.getEntriesByType('resource')`
  捞页面真实 URL 再 import。
- **`position: fixed` 的 `offsetParent` 恒为 null**：用它判面板可见永远得到「不可见」，
  改读 `getComputedStyle(el).display`。
- **`page.evaluate` 回调在浏览器里跑**，访问不到 node 侧变量（`errs is not defined`）。

## 修复：挖掉的方块活不过存档往返（导出导入后沟长回去）

### 根因
`generate.setBlock` 挖空一格写的是 `edits.set(k, 0)`（值 0 表示「这里被我挖成空气」，
不能删掉这条，否则 `getEffective` 分不清「原本没东西」和「被我挖空」）。
而 `save.applySave` 恢复覆盖层写的是 `if (id > 0) m.set(...)` —— 把 0 全丢了。
于是挖出来的沟读档后回落到程序化地形、长回原样；放上去的方块 id>0 一路畅通，
所以「沟没了、塔还在」。`applySave` 被 `loadGame` / 导入共用，F9 读档同样会丢。

**存档文件一直是好的** —— 导出内容里就带着 `["5,18,5",0]`，丢数据发生在读档。
所以现有 .json 不用重导，换版本即可。

### 做法
`save.js` 恢复覆盖层改为：只挡负数 / NaN / 非字符串键 / 超界 id（`isBlockId`），
**0 必须放行**。顺手补上原来缺的两道护栏（旧 `id > 0` 挡不住 99999 和数字键）。

### 验证
- `.scratch/savehole/probe.mjs` 21 项全过（修前 15 过 6 挂）；saveio 探针 19 项无回归
- 浏览器端到端：改动 62 格往返后仍 62 格，50 格挖空逐格为空气、3 格柱子仍在，零报错
- 三段对照截图（挖好的坑 / 往返后 / 按旧逻辑复刻的 bug），中央区域像素差
  2.75% vs 30.20% —— 往返后的画面就是原来那个坑

### 坑
- **像素比对不能直接当「世界变没变」的指标**：树叶摇曳取 `uTime`、手摆取
  `worldTime`，任意两帧都有全局细微差异（37% 像素超阈值，肉眼却看不出）。
  必须同时拍「确实变坏了」的对照组 C，用 `diff(A,B) ≪ diff(A,C)` 说话。
- 对照组要**精确复刻**旧逻辑：第一版直接 `clear()` 把柱子也删了，那不是旧 bug 的样子。
- 坑在画面里太小时，摇曳噪声会盖过信号 —— 相机拉近 + 只统计坑所在区域。
