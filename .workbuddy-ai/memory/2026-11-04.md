### 踩坑
- **`vite preview` 的响应头会骗人**：`curl -I` 有 `Content-Length: 1651`，
  浏览器 `fetch(HEAD)` 却是 `null` —— 浏览器带 `Accept-Encoding`，SVG 被 gzip 成
  chunked 就不发长度了。`Range: bytes=0-0` 能拿总长，但那是**压缩后**的 495 B。
  结论：文本资源的体积不可靠，那一格不报。
- **`scroll-behavior:smooth` 会让无头截图截到半路**：`scrollIntoView()` 后等 600 ms
  不够，截出顶部一大片空白，看着像布局崩了。断言前先把 scrollBehavior 改成 auto
  再 `scrollTo`，并核对 `nav.getBoundingClientRect().top === 0`。
- **`npx vite preview ... &` 起的后台进程会被回收**（探针直接 CONNECTION_REFUSED），
  要用受管后台任务，不能用 shell 的 `&`。

## 部署到 Cloudflare Pages（续）

### 部署前发现工作区里有并行会话的未提交代码
`src/game/chests.js`（253 行）以及 actions / config / textures / uiState / boot /
engine / index / save / App.vue 都在被另一个会话实时改写（文件时间就在几分钟内）。
直接 build + deploy 会把这份**进行中的箱子系统**发到线上。做法：`git worktree add`
到仓库外、单独检出当前提交、junction 一份 `node_modules`、在那里 build，
只部署那份 dist。全程不动对方的工作区。

- 建联接：PowerShell `New-Item -ItemType Junction`（Git Bash 会把 `mklink` 的 `/J`
  当成路径转换掉，报「无效参数」）。
- **删联接必须用 .NET 的 `Directory.Delete(path, false)`**，绝不能用 `rm -rf` 或
  `Remove-Item -Recurse` —— 会顺着链接删进真实的 node_modules。删前先确认
  `Get-Item` 的 `LinkType` 是 `Junction`。
- 先停掉占用该目录的 preview 进程，否则 `git worktree remove` 报 Permission denied。

### Cloudflare Pages 的两个线上特性
- **`/intro.html` 返回 308 → `/intro`**（Pretty URLs 去掉 `.html`），跟随重定向后
  200 正常。链接写 `/intro.html` 在 dev / preview / 线上都能用，只是线上多一跳
  （308 会被浏览器永久缓存，实际只付一次）。
- **HEAD 请求拿不到 `Content-Length`**：线上 `demo.mp4` 的 HEAD 走分块传输、没有
  这个头（而 `.webp` 反而有）。带 `Range` 的请求会返回 200 + `Content-Length`。
  体积一栏因此改成：HEAD 取不到就带 `Range: bytes=0-0` 再取一次，拿到头立刻
  `body.cancel()` 掐断，不能真把 4.6 MB 下完。

## 取消转视角的两处限制（自由视角）

用户确认两处都取消：俯仰 ±90° clamp + 触屏单次 90px 封顶。
工单 `.scratch/free-look/spec.md`，探针 `.scratch/free-look/probe.mjs`。

### 关键结论（推翻旧约定）
- `.scratch/look/spec.md` 写的「PITCH_LIM 不能真删，±90° 会让视图矩阵退化」是错的：
  `M4.view` 的 r/u/f 在任意 pitch 下单位正交（u = r×f，|u|≡1）；pitch=π 时
  r=(1,0,0) / u=(0,-1,0) / f=(0,0,1)。越过 90° 画面倒置是连续旋转的自然结果，
  射线与 view.dir 同源，准星不会对不上。MEMORY.md 对应条目已改写。
- 删封顶有配套：`touchstart` 必须处理「touchend 被吞 + 新手势复用同 identifier」，
  否则基准停在几百像素前，第一次 touchmove 就能一次甩飞（实测 20px 出 -60.9°）。
- yaw / pitch 都折回 [-π,π)（等价角折叠，不是限制）；非有限输入归零防 NaN 进存档。
- 行为取舍：越过 ±90° 后画面上下颠倒。要「无限翻转」又要「画面永远正立」不可兼得。

### 验证
TDD 两轮红→绿（6 条 → 3 条失败），最终 15 条全过：浏览器真触摸 +
合成 TouchEvent 造出「结束事件被吞」。`npx vite build` 111 modules 通过、
`npm run check:curriculum` 通过、既有 `.scratch/look/probe.mjs` 9 条回归全过
（一路下滑到底从 -90° 变 -101.5°，会翻过正下方，断言仍成立）。
双轴 code-review 各派一个子代理，提出的 yaw 数值一致性 / NaN 污染 /
id 复用兜底三处问题已全部修掉并补测。

### 踩坑
- 断言口径：id 复用场景要比较「基准刷新后那 20px 的增量」，把前一段正常滑动
  100px 的 -14.5° 算进去会假失败。
- 改完源码后必须重启 dev server 再跑 probe，否则 HMR 第二实例读到旧状态。
- 合成 `TouchEvent` 才能精确造出「不发 touchEnd 又用同一 id 重新按下」，
  CDP 的触摸点状态机做不到。
