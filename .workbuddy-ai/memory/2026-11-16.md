## 性能优化：结构查询记忆化 + 区块本地方块缓存 + 脏区块时间预算
- 用户反馈：线上 `https://voxel-craft-516.pages.dev/` 卡顿。DevTools 剖析显示**脚本执行 10,572ms 占 94%**，渲染仅 2.8%、绘制 1.1% → 瓶颈在主线程 JS，**不是 GPU**。
- 诊断路径：`node --cpu-prof` 采样「构建 64 个 chunk」→ 自写 `.cpuprofile` 解析器排序 → `structAnchor`+`structAt` 占 **60% 自耗时**。三条放大路径：① `structAnchor` 把 `structAt` 调两遍（判空一次、取 type 又一次）；② `structAt` 无缓存，而 4×4 区块窗口只覆盖 25 个结构格、命中率近 100% 却一次没命中；③ `buildChunk` 对每个实心方块发起约 **78 次 `getEffective`**（自身 + 6 面邻居 + 每面 4 顶点 × 3 次 AO 采样），每次都重扫 9 个结构格 + 25 棵树。
- 改动 1（`src/game/dims.js`）：`structAt` 改为带 `Map` 记忆化的包装，原函数体搬到 `structAtRaw`；缓存**必须跟 `SEED` / `flatWorld` 换桶**（换种子后「泡在水里不建」判定跟着变，沿用旧桶会读到上一轮判定，症状是「换种子地形结构没变」）；上限 600 超限整表清空（结构格密度低，整表清也很快回填）。`structAnchor` 改成只调 `structAt` 一次。
- 改动 2（`src/game/mesher.js`）：`buildChunk` 开头一次性采样 chunk+1 格边进 `Int16Array`（NX/NY/NZ = CW/CH/CD + 2），面剔除邻居查询与 AO 的 `sd()` 全部改走数组下标。**1 格边够用**（AO 沿面切线最多偏移 1 格）；Int16 足够（方块 id 300 出头）；地形是纯函数，采样一次与每次现算等价。
- 改动 3（`src/game/loop.js`）：脏区块重建从「每帧最多 4 个区块」改成**时间预算** `BUILD_BUDGET_MS = 6`（原来 4 个区块 = 56~290ms，一帧就能打到 3~18fps）。走完一格脏 16 个区块，按 6ms/帧摊完需十几帧，期间边界区块是旧的 —— 「视野边缘暂时没长出来」远好于整帧卡死。
- **实测收益（浏览器真实模块，非 Node 模拟）**：单 chunk 网格构建 72.6ms → **12.3ms**（5.9×）；挖/放方块单帧 87ms → **11.7ms**（该帧帧率上限 11.5fps → **85fps**，7.4×）；走路撞格分摊到每帧 535ms → 48ms（11×）；启动预构建 64 chunk 4644ms → ~790ms。
- 正确性：`.scratch/perf/proto.mjs` 逐顶点对拍 —— 30,000 坐标 0 不一致、64 chunk 顶点/索引 0 不一致；`mine-density` 探针确认结构分布未变（矿井 20.1%，阈值 ≥18%）。
- **排除项（有依据地否定，别再提）**：降渲染倍率/关泛光/关 FXAA（渲染只占 2.8%）；缩短视距 `VIEW_CX/CZ` 4→3（区块 64→36 但视野边界肉眼可见推近）；Web Worker 化网格构建（要动整条生成链依赖方向，风险远大于收益）；给 `getEffective` 加全局缓存（它读 `edits` 覆盖层是**有状态**的，会返回过期方块 —— P1 的区块局部缓存每次重建都重新采样，无此问题）。
- 回归：`mine-density`(10/10)、`mob-cap`(ALL PASS)、`spell-craft`、`boss`、`bots`、`portal-nudge`、`transport`、`flat-stick` 全过；浏览器端 3 秒内 **0 个 longtask**、零控制台报错；`vite build` 116 modules（index 260.12 kB / gzip 98.91 kB，与优化前一致）。
- 探针坑：`buildChunk` **不清** `dirty` 标志（清 dirty 的是 `uploadChunk`），探针里 `cleanAll()` 必须手动置 `c.dirty=false`，否则状态污染；挖方块坐标要落在区块窗口内，否则 `dirtyChunkOf` 找不到。headless 是 SwiftShader 软件渲染，**线上 fps 数字不代表真实 GPU 环境**，结论一律以 Node CPU profile + 无头探针（真实源码路径）为准。
- 方案文档：`.scratch/perf/spec.md`（Problem/Solution/User Stories/Implementation/Testing/Out of Scope/Notes）。
- **同机 A/B 对照**（`git worktree add <仓库外路径> HEAD~1` 检出优化前源码 → 起独立端口 dev server → 与新版**串行**跑同一探针）：单 chunk 153.6ms → 13.7ms（**11.2×**），挖方块单帧 70.2ms → 11.9ms，该帧帧率上限 14fps → 84fps。本机 CPU 比首轮慢所以"优化前"绝对值偏高，但两端同机串行，**比值可信**。
- 线上验收（`online-frames.mjs` 纯 DOM，`CF_URL=https://voxel-craft-516.pages.dev/`）：静置 47 帧 / 行走 43 帧，**longtask 0 个、>100ms 的帧 0 个**、零控制台报错。headless 是 SwiftShader 软件渲染，帧间隔 64~80ms 是 GPU 侧固定开销，不代表真实显卡；但"主线程无长任务"与 GPU 无关，可信。
- 部署：`npx wrangler@3 pages deploy dist --project-name voxel-craft --branch=main` → `https://2cb8c83b.voxel-craft-516.pages.dev`；线上 `assets/index-DuR3mYhL.js` 与本地 dist **sha256 完全一致**（`45444a97...`），确认优化已上线。分支 `feat/db` 已推到 `origin/main`。
- **对照环境清理**：worktree 里的 `node_modules` 是指向主仓库的符号链接，删 worktree 前必须先 `rm` 掉它，否则会删进真实依赖；`git worktree remove --force` 后 `git worktree list` 只剩主仓库。

## 别名恢复弹窗（本机别名档案 + 进游戏时问要不要加载）
- 需求：浏览器上设过别名 → 进游戏弹窗问「要不要加载」；从没设过 → 提示设置别名，并说清「设了能存档（云端备份 + 换设备找回）」。
- **根因**：既有 `showGuide` 判的是「**云端当前 owner** 有没有别名」（`getAlias()` 网络查询），不是「**这台浏览器设过没有**」—— 断网/换设备/认领别人的档时前者恒为无，老玩家被误判成新玩家。`save.js` 的展示缓存 `voxel-craft:alias` 也救不了：只存别名文本、**不存 owner**，且 `setOwner()` 换身份时清掉 → 无法从本机反查回自己的档。
- 解法：新增 `src/game/aliasState.js`（**纯函数叶模块，零 import** → 浏览器与 node 探针都能直接 import，**不必经 engine 门面**）+ `src/components/AliasResume.vue`（独立组件，z-index 45）+ `save.js` 三个 seam（`setAlias` 成功写档案 / `deleteSave` 清档案 / `setOwner` **不**清档案）+ `App.vue` 挂载。
- **两套语义必须分开**：`voxel-craft:alias`（展示缓存，「我现在这份档叫什么」，随身份变、setOwner 清）↔ `voxel-craft:alias-state`（本机档案，「这台机器上我用过什么名字 + 它绑的 owner」，**不随身份变**，是换回自己存档的钥匙）。只存别名文本无法反查存档 —— 必须连 owner 一起存。
- **「先不用」之后还弹不弹分两种情况**（关键设计，差别在**面板上有没有等价入口**）：身份一致 → 面板上有「继续上次存档 / 从云端继续」走同一条路，拒绝过一次就别再弹（`refused && ownerMatches()` 才 return）；身份已换（认领过别人的档）→ 面板那俩按钮指的是**别人的**档，弹窗是回自己那份的**唯一通路**，**必须每次都弹**。`dismiss()` 里同样带 `ownerMatches()` 判断。
- **加载路径必须按身份分流**：身份一致 → `loadNow()`（本机档，秒开、离线可用）失败回落 `loadFromCloud()`；身份已换 → **只能走云端**（localStorage 里那份是「别人的世界」），必须先 `setOwner(档案.owner)` 换回去，拉不到就把身份换回原值，绝不把玩家留在空档位。
- **`nothingToLoad`（自查补的 UX 缺口）**：设了别名但账号下无档（本机无 + 云端 `has:false`）时不该问「要不要加载」—— 点了必然得到「没找到这份存档」。改成如实告知 + 按钮变「知道了」。⚠ **offline 不算「没有」**：云端不可达时不知道有没有，按「可能有」处理，否则离线玩家永远加载不了自己的档。
- **与 StartVeil 行内引导的分工**：那边已有同义的行内提示，本组件 setup 阶段 `suppressInlineGuide()` 压掉它，引导语只留一处。⚠ **必须挂在 `<StartVeil />` 之前** —— StartVeil 只在自己 `setup()` 里读一次引导标记，顺序反了压不住。
- **并行会话冲突规避**（本条是重点教训）：同时有另一个会话在改 `StartVeil.vue`/`engine.js`/`index.js`/`uiState.js`/`loop.js`/`generate.js`/`post.js`/`nametags.js`/`vite.config.js`/`wrangler.toml`（多人房间功能 + Windows 盘符大小写修复）。本功能线**完全不碰**这些文件，靠「新建纯函数叶模块可静态 import，不必经 engine 门面」绕开。提交时**只 `git add` 自己那 4 个文件 + `.scratch/alias-resume/`**，绝不能 `git add -A`。
- **`vite.config.js` 当时是语法错误状态**（并行会话半成品：`const root = dirname(...)` 后面直接接 `.replace(...)`，ASI 救不了）→ 全量构建必然失败且与本功能无关。绕法：`.scratch/alias-resume/vite.shadow.mjs` 影子配置（放 `.scratch/` 下是为了 node 向上解析到仓库根 `node_modules`），`npx vite --config .scratch/alias-resume/vite.shadow.mjs` 起 dev server。隔离环境构建（HEAD 版配置 + 当前 `src/`）**125 modules transformed**，index 265.69 kB / gzip 101.24 kB。
- **探针坑（三个都踩过）**：
  ① 同一个 page 反复 `addInitScript` 会**累积** —— 后面的场景会看到前面场景留下的状态，断言不可信。改成**每场景一个独立 context**（localStorage 天然隔离）。
  ② dev server 没有 `/api/save`，返回 index.html → `cloudMeta()` 解析失败只落到 `offline`，**永远测不到「云端确实没有这份档」**。改用 `ctx.route()` 拦截模拟云端（业务失败仍 200 + body，与线上一致）。
  ③ **Vue 渲染批处理**让同一微任务里的多次 `toast()` 只渲染最后一版 —— `loadNow` 的「📂 已读档」会被组件的「✓ 已载入」顶掉，MutationObserver 也抓不到中间态（它从未进 DOM）。探针改成验**存档内容落到 UI 上的投影**（模式按钮高亮 / 超平坦高亮 / 快捷栏第 1 格是苹果 ×3）。顺带说明：这对用户是好事，不会闪两下。
- 验证：`.scratch/alias-resume/probe.mjs` **65 项全过**（含组件关键判据的源码静态检查）；`.scratch/alias-resume/ui-probe.mjs` **9 个场景全过**，每场景独立 context + 路由拦截模拟云端，**零控制台报错**。spec：`.scratch/alias-resume/spec.md`。
