## 性能优化：结构查询记忆化 + 区块本地方块缓存 + 脏区块时间预算
- 用户反馈：线上 `https://voxel-craft-516.pages.dev/` 卡顿。DevTools 剖析显示**脚本执行 10,572ms 占 94%**，渲染仅 2.8%、绘制 1.1% → 瓶颈在主线程 JS，**不是 GPU**。
- 诊断路径：`node --cpu-prof` 采样「构建 64 个 chunk」→ 自写 `.cpuprofile` 解析器排序 → `structAnchor`+`structAt` 占 **60% 自耗时**。三条放大路径：① `structAnchor` 把 `structAt` 调两遍（判空一次、取 type 又一次）；② `structAt` 无缓存，而 4×4 区块窗口只覆盖 25 个结构格、命中率近 100% 却一次没命中；③ `buildChunk` 对每个实心方块发起约 **78 次 `getEffective`**（自身 + 6 面邻居 + 每面 4 顶点 × 3 次 AO 采样），每次都重扫 9 个结构格 + 25 棵树。
- 改动 1（`src/game/dims.js`）：`structAt` 改为带 `Map` 记忆化的包装，原函数体搬到 `structAtRaw`；缓存**必须跟 `SEED` / `flatWorld` 换桶**（换种子后「泡在水里不建」判定跟着变，沿用旧桶会读到上一轮判定，症状是「换种子地形结构没变」）；上限 600 超限整表清空（结构格密度低，整表清也很快回填）。`structAnchor` 改成只调 `structAt` 一次。
- 改动 2（`src/game/mesher.js`）：`buildChunk` 开头一次性采样 chunk+1 格边进 `Int16Array`（NX/NY/NZ = CW/CH/CD + 2），面剔除邻居查询与 AO 的 `sd()` 全部改走数组下标。**1 格边够用**（AO 沿面切线最多偏移 1 格）；Int16 足够（方块 id 300 出头）；地形是纯函数，采样一次与每次现算等价。
- 改动 3（`src/game/loop.js`）：脏区块重建从「每帧最多 4 个区块」改成**时间预算** `BUILD_BUDGET_MS = 6`（原来 4 个区块 = 56~290ms，一帧就能打到 3~18fps）。走完一格脏 16 个区块，按 6ms/帧摊完需十几帧，期间边界区块是旧的 —— 「视野边缘暂时没长出来」远好于整帧卡死。
- **实测收益（浏览器真实模块，非 Node 模拟）**：单 chunk 网格构建 72.6ms → **12.3ms**（5.9×）；挖/放方块单帧 87ms → **11.7ms**（该帧帧率上限 11.5fps → **85fps**，7.4×）；走路撞格分摊到每帧 535ms → 48ms（11×）；启动预构建 64 chunk 4644ms → ~790ms。
- 正确性：`.scratch/perf/proto.mjs` 逐顶点对拍 —— 30,000 坐标 0 不一致、64 chunk 顶点/索引 0 不一致；`mine-density` 探针确认结构分布未变（矿井 20.1%，阈值 ≥18%）。
- **排除项（有依据地否定，别再提）**：降渲染倍率/关泛光/关 FXAA（渲染只占 2.8%）；缩短视距 `VIEW_CX/CZ` 4→3（区块 64→36 但视野边界肉眼可见推近）；Web Worker 化网格构建（要动整条生成链依赖方向，风险远大于收益）；给 `getEffective` 加全局缓存（它读 `edits` 覆盖层是**有状态**的，会返回过期方块 —— P1 的区块局部缓存每次重建都重新采样，无此问题）。
- 回归：`mine-density`(10/10)、`mob-cap`(ALL PASS)、`spell-craft`、`boss`、`bots`、`portal-nudge`、`transport`、`flat-stick` 全过；浏览器端 3 秒内 **0 个 longtask**、零控制台报错；`vite build` 116 modules（index 260.12 kB / gzip 98.91 kB，与优化前一致）。
- 探针坑：`buildChunk` **不清** `dirty` 标志（清 dirty 的是 `uploadChunk`），探针里 `cleanAll()` 必须手动置 `c.dirty=false`，否则状态污染；挖方块坐标要落在区块窗口内，否则 `dirtyChunkOf` 找不到。headless 是 SwiftShader 软件渲染，**线上 fps 数字不代表真实 GPU 环境**，结论一律以 Node CPU profile + 无头探针（真实源码路径）为准。
