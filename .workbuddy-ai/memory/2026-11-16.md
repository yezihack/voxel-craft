## 移除导出/导入存档 + 新增 UUID 别名绑定与首次引导
- 用户要求：云端存储已上线，去掉「导出存档 / 导入存档」；给难记的 UUID 加一个可自行设置、绑定的别名，首次使用时引导。
- 移除链路：`StartVeil.vue` 的按钮与隐藏 file input、`engine.js` 的 NOT_READY_KEYS、`game/index.js` 门面导出、`uiActions.js` 包装函数。`save.js` 的 `exportSaveJson/importSaveJson` **保留**作纯编解码（saveio/savehole 探针依赖字段级容错），注释写明应用侧别再接 UI。
- 新增 `migrations/0002_aliases.sql`（`alias` 归一化主键 + `owner` UNIQUE + `display` + `created_at`）、`functions/api/alias.js`（GET 查/解析、PUT 绑定改名、DELETE 解绑；改名在同一 `db.batch()` 里先删后插）、`src/game/aliasName.js`（`normalizeAlias` 2–20 字 `\p{L}\p{N}_-`、`isOwnerCode`，前后端共用）、`save.js` 的 `getAlias/setAlias/lookupAlias/resolveOwner` 与 `ALIAS_KEY` 离线展示缓存。
- `StartVeil.vue`：云端行 = 状态 + 别名 chip + 认领，存档码降到第二行；首次引导 `showGuide`（无别名 & `engineReady` & 云端可达 & 未点「暂不」），「暂不」写 `voxel-craft:alias-guide` 永久收起；认领接受别名或存档码，解析不到档就还原 owner，有档才 `loadFromCloud()` 后 `startGame()`；`refreshCloud()` 顺带重查别名，认领后 chip 立即换成新 owner 的名字。
- **业务失败改 200 + body reason**：`taken` 原 409、`invalid` 原 400 会被浏览器记成控制台资源错误，零报错验收过不了（与空档 GET 404→200 同一原则）；`setAlias()` 改为只判 `!r.ok` 再解 body。只有 D1 未绑定 / DB 异常保留 5xx。
- 认领框先 `isOwnerCode` 再判别名：否则 `myworld123` 这类 10 字符纯字母别名会被当成 owner 直接写进 `x-owner` 头，去找一份不存在的档。
- 验证：`.scratch/alias/probe.mjs` 23/23；`vite build` 116 modules（index 259.61 kB / gzip 98.70 kB）；本地 0002 迁移 + `/api/alias` curl 全链路；`ui-probe.mjs` 本地 15/15、线上 15/15 且零控制台报错。
- **探针坑**：两个 WebGL 页面同时开 + swiftshader 会把第二页卡到完全不渲染（表现为 `waitForSelector('.veil .panel h1')` 超时且零控制台报错）。改成 A 验证完立即 `ctx.close()`、纯 API 走 Node `fetch`、等待放宽 45s 才稳定。
