# 让史莱姆和蜘蛛掉进 1 格宽的沟

## 需求

> 让史莱姆和蜘蛛在走过一格宽的沟时会掉进去，而不是直接跨过去。

用户确认的两条口径：

- 验证 seam：**纯 Node 物理探针**（stub 掉 DOM / WebGL / 音频，直接 import 真游戏模块驱动 `mobPhysics` / `mobAI`）。
- 「掉进去」语义：**掉进去即算达成** —— 只要求明显踏空下坠到沟里，不额外削弱既有起跳 / 爬墙能力，不把沟做成绝对陷阱。

## 根因

`mobPhysics(m, dt)` 的贴地探测扫的是 AABB 覆盖的整片格子，只要**任意一格**脚下实心就判 `grounded = true`，随后直接 `m.y = footY + 1`、`m.vy = 0`：

```js
const x0 = Math.floor(m.x - hw), x1 = Math.floor(m.x + hw - 1e-6);
for (let z = z0; z <= z1 && !grounded; z++)
  for (let x = x0; x <= x1; x++)
    if (isSolid(getEffective(x, footY, z))) { grounded = true; break; }
if (grounded && m.vy <= 0.01) { m.y = footY + 1; m.vy = 0; m.onGround = true; }
```

蜘蛛 `w = 1.10`（半宽 0.55）、大史莱姆 `w = 1.00`（半宽 0.50）比一格还宽。跨 1 格宽的沟时 AABB 从头到尾同时压着两岸的实心块，「支撑」恒为真 → 永远进不了下落分支，等于**凭空架了一座隐形桥**。小史莱姆 `w = 0.55`、僵尸 `w = 0.62` 本来就窄，AABB 搭不起两岸，红阶段照样掉进去。

还有三条挡路的连带机制，只收窄 `hw` 不足以修好：

1. **Y 轴扫掠把下落的生物顶回地面**：`moveBodyAxis(m, hw, ..., 'y', ...)` 用的是整只 AABB；刚开始下落时边缘一擦到对岸方块就被回退到 `y = 31`。
2. **贴地吸附会「上拽」**：掉进沟之后 AABB 又擦到岸，`grounded` 重新为真，旧写法无条件 `m.y = footY + 1`，把已经掉下去半格的生物直接拉回地面高度。
3. **蜘蛛顺沟壁爬回去**：`climb` 分支撞到沟壁就 `moveBodyAxis(..., 'y', SPIDER_CLIMB * dt)`，刚掉半格就被拉回地面。

## 做法

### 1. `MOB_TYPES.squeeze`（新 flag，只标蜘蛛 + 大史莱姆）

`w` 仍是渲染 / 命中盒宽度，不动；物理半宽另算：

```js
const hw = D.squeeze ? Math.min(D.w / 2, SQUEEZE_HW) : D.w / 2;   // 水平 + 贴地
const vertHW = D.squeeze ? CENTER_HW : hw;                          // 竖直
```

- `SQUEEZE_HW = 0.4`：留出 0.1 格余量，重心进入沟列 `x ∈ [0.4, 0.6)` 时 AABB 完全落在沟列里，水平扫掠不会刮到沟壁（否则会被 `moveBodyAxis` 一把推回岸上，表现成「掉下去又被弹回来」）。
- `CENTER_HW = 0.02`：Y 轴扫掠只看中心列，竖直方向只看得到沟底，不会被两岸顶回地面。

**贴地探测仍沿用 `hw`（SQUEEZE_HW），不改成中心列**：这对刚体是对的 —— 只要还有一只脚搭在岸上就不该失足。试过把贴地也收成中心列，蜘蛛会在沟口过早踏空，此时水平 AABB 还压着沟壁，被 `moveBodyAxis` 直接推回岸上，反而更走不进沟。

小史莱姆 `w = 0.55` 本来就掉得进去，**不挂 `squeeze`、物理原样不动**。曾给它挂上，虽然探针也全绿，但会白白把它原本 `hw = 0.275` 的竖直扫掠改成中心列，是没必要的行为变更，已撤回。

### 2. 禁止上拽（只对 squeeze 生物）

```js
if (grounded && m.vy <= 0.01 &&
    (!D.squeeze || m.y >= footY + 1 - GROUND_SNAP_TOL)) { ... }
```

`GROUND_SNAP_TOL = 0.06`。吸附只负责消掉「站在地上」那 2 毫米的累积误差；身体已经低于该格顶面超过这个容差时，说明真的在往下掉，不许把它设回地面高度。

`D.squeeze` 守卫是代码审查后补的：这条判据本来写成全局，会把小史莱姆 / 僵尸 / 骷髅的贴地行为一并改掉，超出「让史莱姆和蜘蛛…」的范围。加上守卫之后，**非 squeeze 生物的 `hw` / `vertHW` / 吸附全部与改动前逐字一致**，改动面只剩蜘蛛和大史莱姆。正常落地由 `moveBodyAxis` 的碰撞回退负责，探针另用「上 1 格台阶」验证吸附没被禁掉。

### 3. 沟内禁爬 `inShaft`（只在 `D.climb` 分支，实际只影响蜘蛛）

沟是 1 格宽竖井，身体那一层的 `cx-1` 与 `cx+1`（或 `cz-1` 与 `cz+1`）都是实心 —— 这是「被夹在沟底」，不是「面前有一堵墙」：

```js
const solid = (x, y, z) => isSolid(getEffective(x, y, z));
const inShaft =
  (solid(cx - 1, hy, cz) && solid(cx + 1, hy, cz)) ||
  (solid(cx, hy, cz - 1) && solid(cx, hy, cz + 1));
if (!inShaft && (...原来的爬墙判据...)) { ... }
```

站在一堵墙外时只有一侧是实心，不会命中。回归探针验证 3 格高墙仍能爬、1 格台阶仍能上。

⚠ 试过把判据收窄成「两侧上方也是空气」，用来放行 1 格宽走廊；结果**只在沟口第一层成立**，掉到第二层之后两侧上方就是地表石头，蜘蛛会被误判成在走廊里、又顺着沟壁爬回去。已回退，判据保持原样。

## 代码审查结论

两轴审查后的处置：

| 发现 | 处置 |
| --- | --- |
| `0.06` 是裸魔数，与 `SQUEEZE_HW` / `CENTER_HW` 命名风格不一致 | 提为 `GROUND_SNAP_TOL` |
| 禁止上拽全局生效，超出需求范围、也和「小史莱姆物理原样不动」自相矛盾 | 加 `D.squeeze` 守卫 |
| `inShaft` 会在 1 格宽走廊误禁爬墙 | 试过收窄，会放跑深沟里的蜘蛛；保留原判据，记为已知边界 |
| 探针只验证「掉进去」，没验证「不额外削弱起跳 / 不做成绝对陷阱」 | 补第 5 组 10 条断言 |
| 竖直扫掠收成中心列是否会在窄平台边缘漏下去 | 中心列只在 squeeze 生物**已判失足**时参与 Y 轴扫掠；贴地探测仍用 `hw = 0.4` 的全脚掌，平地 / 台阶 / 高墙 / 平地推进均有断言覆盖 |
| 命中盒仍按 `D.w/2`，物理半宽 0.4，钻沟时判定与身位略有偏差 | 接受：`w` 是渲染与命中盒宽度，需求只要求「掉进去」，改它会波及攻击 / 受击判定 |
| `spec.md` 顶部 `Status: resolved` 不符合 issue 文件的 label 约定 | 删掉，spec 不是 issue file |
| 探针头部注释写 `y < 29.5`，代码是 `START_Y - 0.6 = 30.4` | 改一致 |

`runChase` / `runCustom` / `runAfterFall` 三个驱动同构，属测试代码里的判断性重复，未抽取公共函数（抽取后各场景的采样口径反而更难读）。

## 边界

- 只改物理碰撞箱，渲染 / 命中盒宽度不变；蜘蛛腿、史莱姆边缘轻微嵌进沟壁是可接受的。
- 沟不是绝对陷阱：1 格深沟里蜘蛛与小史莱姆都能自己出来，跳得出去 / 之后爬得出去都不算回归。
- 飞行 boss 走 `D.fly` 短路且无 `squeeze`，两处改动都影响不到；其余非 squeeze 生物的物理与改动前逐字一致。
- `inShaft` 的几何判据在 1 格宽走廊（身体层两侧都是墙）里也会命中，那里蜘蛛的 2 格以上爬墙会被一并禁掉；1 格台阶走起跳分支不受影响。按「沟优先」取舍，未为走廊引入状态位。
