# 手机竖版：生命值压住摇杆/动作键、物品栏首尾格被裁

## 现象
竖屏手机上：
1. 生存模式的 10 颗心 + 10 个鸡腿横在屏幕中部，**正压着左摇杆和右下「挖 / 放」**。
2. 窄屏（≤360 宽）时底部 9 格物品栏宽 368px，**第 1 格和第 9 格被屏幕边缘裁掉**。

## 根因
- `Vitals.vue` 的触屏断点写的是 `bottom: 100px`，而 `TouchControls.vue` 里
  摇杆和 2×2 动作区的底边也正好是 `100px`。三者同一条水平带 → 心形必然横穿按钮。
  横屏时按钮在两侧、中间有缝，看不出来；**竖屏中间只剩几十像素，怎么放都压**。
- 物品栏格子固定 36px（≤560px 断点），9 格 + 间隙 + 内边距 = 366px。
  360 宽的安卓机（主流）溢出 6px，320 宽（iPhone SE）溢出 48px。

## 做法
### 生命值挪出拇指区
触屏（`ui.touch`）时 `.vitals` 加 `.touch` 类，改到**左上角**：
- `left: 10px` / `top: 52px`，图标 16px → 13px（10 颗心 178px → 139px）。
- `top` 取 52 而不是 8：360 宽时右上系统栏（210px 宽，右对齐）一直伸到 x=138，
  而 10 颗心到 x=149，贴顶就会撞 10px，下移一行彻底分开。
- 删掉原来的 `@media (pointer: coarse) { bottom: 100px }`。

### 物品栏再缩两档
`ItemSlot.vue` 增加：
- `@media (max-width: 400px)` → 32×40，`--ic: 20px`（9 格 332px，360 屏可用 348）
- `@media (max-width: 350px)` → 28×36，`--ic: 18px`（9 格 286px，320 屏可用 308）

`HotBar.vue` 同步收间隙与内边距（400px 档 gap 4/padding 5，350px 档 gap 3/padding 4）。
不给容器设 `max-width` —— flex 不会自动缩子元素，设了只会让背景比内容窄。

## 验证
`.scratch/mobile/check.mjs`（真 Chromium，`hasTouch`，量 bounding rect + 两两重叠）：

| 视口 | 结果 |
|---|---|
| 320×568 竖屏生存 | 无重叠、物品栏 286 宽在屏内 |
| 360×740 竖屏生存 | 无重叠、物品栏 332 宽在屏内 |
| 390×844 竖屏生存 | 无重叠 |
| 640×360 小横屏 | 无重叠（回归） |
| 844×390 横屏 | 无重叠（回归） |

`npx vite build`：100 modules，CSS 20.73 kB（+0.13 kB）。

## 踩坑
- `import('/src/engine.js')` 在 dev 下会拿到**与组件不同的模块实例**
  （vite 的 HMR query 不同），读到的是 `NOT_READY_KEYS` 占位 noop，
  看起来像「引擎没初始化」。判断「按钮能不能点」只能靠 DOM 观察，别 import。
- 等「地形就绪」要**连续 3 次采样一致**才算稳定。只等一次会在进度条抖动时
  假通过，接着点开始按钮正好撞上面板重渲染，看着像按钮没反应。
