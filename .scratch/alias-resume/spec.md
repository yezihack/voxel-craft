# 别名恢复弹窗（Alias Resume）

> Status: ready-for-agent

## Problem

玩家在浏览器上设置过存档别名后，下次进游戏没有任何提示，必须自己想起来去面板里点「继续上次存档」；换设备时更是完全不知道有这份档存在。

同时存在一个**判定口径错误**：`StartVeil.vue` 的 `showGuide` 判断的是「**云端当前 owner** 有没有别名」（`aliasName` 来自 `getAlias()` 的网络查询），而不是「**这台浏览器是否设置过**」。断网 / 换设备 / 认领了别人的档时前者恒为无 —— 老玩家会被误判成新玩家。

已有的 `save.js` 展示缓存 `voxel-craft:alias` 也救不了这个场景：它只存别名文本、不存 owner，且 `setOwner()` 换身份时会把它清掉 → **无法从本机反查回自己的档**。

## Solution

新增一份**本机别名档案**（别名 + 它绑的 owner + 时间戳），并在引擎就绪后按档案状态弹一个对话框：

| 局面 | 弹窗 | 说明 |
| --- | --- | --- |
| 这台机器设过别名 | 「🏷 继续上次存档？」 | 显示档在哪儿（本机 / 云端 / 需切回账号），给「加载这份存档」与「先不用」 |
| 从没设过别名 | 「🏷 给存档起个名字」 | 说清价值：进度自动同步到云端，换设备输入这个名字就能找回 |
| 设过别名但账号下无档 | 同上，但按钮改成「知道了」 | 不给一个必然失败的「加载」按钮 |

### 关键设计

**① 本机档案与展示缓存语义分离**

- `voxel-craft:alias`（既有，展示缓存）→「**我现在这份档叫什么**」，随身份变，`setOwner` 时清空
- `voxel-craft:alias-state`（新增，本机档案）→「**这台机器上我用过什么名字**」，不随身份变，是换回自己存档的钥匙

只存别名文本无法反查存档 —— 必须连 owner 一起存。

**② 「先不用」之后还弹不弹？分两种情况**

差别在于**面板上有没有等价入口**：

- 身份一致（owner 没换过）→ 面板上有「继续上次存档 / 从云端继续」按钮，走的是同一条路。玩家拒绝过一次就别再弹了。
- 身份已换（认领过别人的档）→ 面板上那两个按钮指的是**别人的**档，玩家想回自己那份只能靠这个弹窗换回原 owner。**此时必须每次都弹**，否则他自己的档就再也找不回来了。

代码对应：`refused && ownerMatches()` 才 return；`dismiss()` 里同样带 `ownerMatches()` 判断。

**③ 加载路径必须区分身份是否匹配**

- 身份一致 → `loadNow()`（读本机 localStorage 档，秒开、离线可用）→ 失败回落 `loadFromCloud()`
- 身份已换 → **只能走云端**。localStorage 里那份是「别人的世界」，读它等于把别人的存档加载进来。必须先 `setOwner(档案.owner)` 换回去，拉不到就把身份换回原值。

**④ 与 StartVeil 行内引导的分工**

StartVeil 里已有一个行内「首次引导」提示，讲的是同一件事。本组件在 setup 阶段 `suppressInlineGuide()` 把那边的行内提示压掉，引导语只留这一处。

⚠ **必须挂在 `<StartVeil />` 之前** —— StartVeil 只在自己的 `setup()` 里读一次引导标记，顺序反了就压不住。

## User Stories

- 作为在本机设过别名的玩家，我进游戏时看到「要不要加载上次存档」，并且能一眼看出这份档在本机还是云端。
- 作为跨设备玩的老玩家，我在新设备上输入别名就能认领回档；已经有本机记录的设备会主动问我。
- 作为第一次玩的玩家，我被告知设别名的价值是「进度能存下来、换设备能找回」，而不是一句干巴巴的「请设置别名」。
- 作为已经设过别名但还没玩过一局的玩家，我不会被问一个点了必然失败的问题。

## Implementation

| 文件 | 改动 |
| --- | --- |
| `src/game/aliasState.js` | **新增**。纯函数叶模块（无 import），浏览器与 node 探针都能直接 import。档案读写 / 提示状态 / 行内引导抑制，损坏数据一律降级不抛异常 |
| `src/components/AliasResume.vue` | **新增**。独立组件，管理「引擎就绪后、玩家还没进游戏」这个窗口。z-index 45（veil 20 / Toast 26 / DeathScreen 40 / FatalNotice 100） |
| `src/game/save.js` | `setAlias()` 成功后写本机档案（**所有**设别名入口的唯一汇聚点）；`deleteSave()` 清本机档案；`setOwner()` **不**清（换回来还要用） |
| `src/App.vue` | 挂载 `<AliasResume />`，排在 `<StartVeil />` **之前** |

### 为什么独立成组件、不改 StartVeil

`StartVeil.vue` 已经是开始 / 暂停遮罩，而这个弹窗有**自己的生命周期**（只在那个窗口里出现一次）。而且本功能线要避开并行会话正在改的文件（`StartVeil.vue` / `engine.js` / `index.js` / `uiState.js`）—— 新建纯函数叶模块 `aliasState.js` 可以直接静态 `import`，**不必经 engine 门面**，于是完全不用碰并行会话的文件。

## Testing

### 纯逻辑探针 `.scratch/alias-resume/probe.mjs`（65 项）

覆盖档案读写/trim/清除；owner 为空→清空；JSON 损坏 / null / 字符串 / 字段类型错 → 降级不崩；提示状态读写；行内引导抑制；与 `save.js` 展示缓存的语义隔离；`save.js` seam 的源码静态检查；组件关键判据的源码静态检查（身份判定、加载路径、nothingToLoad 不把 offline 当成「没有」）。

### UI 探针 `.scratch/alias-resume/ui-probe.mjs`（9 个场景，真实浏览器）

每个场景一个**独立 context**（localStorage 天然隔离），云端用**路由拦截**模拟 —— dev server 没有 `/api/save`，返回 index.html 会让 `cloudMeta()` 落到 `offline`，那样永远测不到「云端确实没有这份档」这条分支。

| 场景 | 验证 |
| --- | --- |
| ① 新玩家 | 弹「给存档起个名字」、有输入框与「以后再说」、关掉不自己冒回来 |
| ② 设过别名 + 云端有档 | 弹「继续上次存档？」、显示「云端有这份档」、有加载按钮 |
| ③ 身份已换 | 提示会切回原账号 |
| ④ 身份一致 + 已拒绝 | **不再弹** |
| ⑤ 身份已换 + 已拒绝 | **仍要弹**（回自己档的唯一通路） |
| ⑥ 行内引导压制 | StartVeil 的 `.aliasguide` 不出现 |
| ⑦ 端到端 | 真造存档 → 点「加载」→ 模式 / 世界类型 / 背包内容都真的落到了游戏里 |
| ⑧ 有别名但无档 | 如实告知「还没找到」，不给必然失败的加载按钮 |
| ⑨ 设别名 | 本机档案真的落盘（别名 / owner / 时间戳），展示缓存同步 |

每个场景都断言零控制台报错。

**⑦ 的断言不靠 toast**：`loadNow` 发「📂 已读档」、组件紧接着发「✓ 已载入」，两者在同一微任务里，Vue 批处理后 DOM 只有最终值，中间态从没进过 DOM。改成验**存档内容落到 UI 上的投影**（模式按钮高亮 / 超平坦高亮 / 快捷栏第 1 格是苹果 ×3）。

## Out of Scope

- 不改后端协议（`/api/alias` 的 GET/PUT/DELETE 语义不变）
- 不做「别名历史」多档位（当前只记最后一个）
- 不做别名输入的模糊匹配 / 联想
- 不改 StartVeil 面板上既有的「设置别名 / 认领」入口（弹窗只是多一个主动通路）

## Notes

- **`nothingToLoad` 只在「确定没有」时才算**：云端不可达（offline）时不知道云端有没有，按「可能有」处理，照常给加载按钮 —— 否则离线玩家永远加载不了自己的档。
- **`setOwner()` 不清本机档案**：认领别人的档只是临时借用身份，不该把「换回自己档的钥匙」丢掉。真正该清的是展示缓存。
- **本机档案存一份是有意的**：别名全局唯一（后端 `aliases` 表判重），「别名 + owner」足以在换设备时反查回存档。
- **Vue 的渲染批处理**会让同一微任务里的多次 `toast()` 只渲染最后一版 —— 这对用户是好事（不会闪两下），但写探针时不能指望抓到中间态。
